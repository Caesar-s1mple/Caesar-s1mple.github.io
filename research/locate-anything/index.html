LocateAnything:把每个框当原子块,一次前向并行解出

NVIDIA 的统一视觉定位模型——Parallel Box Decoding 块化并行解码、NTP/MTP 联合训练、Hybrid 回退, 与 138M 条查询的数据引擎;一次全景拆解。

Vision Grounding Parallel Decoding 📅 2026-09-03 ⏱ 约 15 分钟 📄 NVIDIA · ECCV 2026(arXiv:2605.27365)
摘要:《LocateAnything: Fast and High-Quality Vision-Language Grounding with Parallel Box Decoding》 是 NVIDIA LPR 实验室(Eagle VLM 团队,通讯作者 Zhiding Yu;Lei Zhang 同时任教于香港理工大学)2026-05-26 挂出的技术报告, 官方口径已被 ECCV 2026 接收。核心主张一句话:VLM 做 grounding 时不该把框序列化成逐 token 蹦出的数字串—— 把每个边界框/点视为定长原子块,单次前向并行解码整个坐标集(Parallel Box Decoding, PBD)。 结果是 3B 模型(MoonViT + Qwen2.5-3B)在 H100 上跑到 12.7 BPS(box/秒), 10× Qwen3-VL、2.5× Rex-Omni,且 LVIS F1@IoU=0.95 从 Rex-Omni 的 20.7 拉到 31.1; 统一覆盖开放词表检测、密集检测、referring grounding、GUI grounding、OCR 定位、文档版面与点定位七类任务。 HF 权重发布一周下载破 10 万。骨干直接站在月之暗面 Kimi-VL 的 MoonViT 与阿里 Qwen2.5 肩上,本文一并拆解。
📑 本文目录

1 · 总览:一次前向,框全出来

生成式 VLM 做视觉定位的通行做法,是把坐标变成文本:要么写成数字(Textual Digits,如 Qwen-VL), 要么量化成离散 token(Quantized Tokens,如 Rex-Omni),然后让语言模型逐 token 自回归地蹦。 一张 300 个目标的密集场景图,意味着上千次串行解码步。LocateAnything 换了一种看法: 一个框本来就是 4 个坐标 + 2 个结构 token 的定长单元,为什么不一次前向把整个块解出来? 这就是 Parallel Box Decoding——块与块之间保持因果(半自回归),块内全部并行。

2 · 动机:串行解码与几何结构天生不匹配

论文的问题意识来自一个观察:框是二维几何对象,而 1D token 流不是。

把 2D 框压平成 1D token 序列有两个代价。其一是结构错配:一个框的四个坐标是强耦合的整体, 逐 token 解码把「当前在写哪个框的第几个坐标」这层状态完全交给模型自己维护,错误会沿序列累积。 其二是吞吐瓶颈:每框至少 4-6 个解码步,目标越多延迟越长——这正是密集检测、整页 OCR、 文档版面这类「框多」场景最疼的地方。

那为什么不直接套用已有的通用加速方案?论文(§1, Fig. 2)明确指出:通用 MTP / 扩散式 LLM 的随机分块是 structure-agnostic 的——块边界可能切在一个框的中间、横跨两个物体、甚至横跨类别, 于是模型学到的是跨框、跨类别的虚假共现模式。LocateAnything 的主张因此非常干净: 并行化的块边界必须与几何单元的边界严格对齐——加速结构本身要懂任务的形状。

3 · 方法:Parallel Box Decoding

3.1 块表示:定长 L=6 的原子块

坐标归一化到 [0,1000] 量化。每个块定长 L=6:4 个坐标 token 加 <box>/</box> 结构 token,空位填 <null>。 在此之上定义四种功能块:Semantic(语义标签,可跨多个块)、Box、 Negative(显式表示「目标不存在」,输出 <box>none</box>)与 End(终止)。联合概率写成 P(B|Z,E)=∏ᵢ P(bᵢ|b<ᵢ,Z,E)——半自回归:块内并行、块间因果。 骨干是原生分辨率 VLM:Moon-ViT(月之暗面 Kimi-VL 的 MoonViT-SO-400M,MIT 许可)+ MLP projector + Qwen2.5-3B-Instruct,总参数 3B,属 NVIDIA Eagle VLM 家族。

3.2 NTP + MTP 联合训练,三条掩码规则

训练输入是拼接序列 x_all = x_vis ⊕ x_q ⊕ x_ntp ⊕ x_blk:同一份 ground truth 同时以 token 级(NTP)与块级(MTP)两种格式出现;MTP 块内保留首 token 作上下文、其余替换为 [mask]。 配套专用注意力掩码(Fig. 4)三条规则:① NTP 流纯因果且不可见 MTP 流(防信息泄漏、兼容 KV cache); ② 块间因果(学框与框的依赖,减少重复/漏检);③ 块内双向(学坐标间的几何依赖)。 损失 L = L_ntp + L_mtp;块长 = 1 时退化为标准 NTP。工程上训练用 MagiAttention 支持异构注意力掩码 + Stream Packing。

3.3 三种推理模式:Slow / Fast / Hybrid

Slow纯 NTP 逐 token 解码;最稳,精度上界,4.3 BPS
·
Fast纯 MTP 块并行;最快,15.3 BPS,但精度略掉
·
Hybrid(默认)MTP 出错则丢弃问题块、回退已验证前缀、NTP 重解码该块后切回;12.7 BPS

Hybrid 的歧义触发条件(论文逐字):top-1 坐标 token 概率 < 0.7 且 top-5 坐标 token 在 [0,1000] 空间的 max-min 差 > 80;或检测到格式违规。它针对的是作者明示的两类并行解码失败模式: Format Irregularity(类别边界处结构 token 与坐标 token 混杂,实例 <box><211></ref><911><887></box>) 与 Spatial Ambiguity(网格状密集排列时输出两物体之间的中间坐标,IoU 骤降)。 推理侧还有纯 FlashAttention-varlen 的 la_flash 后端:A100 4K 图 batch=4 时 8.03 s / 11.71 GB 显存, 对比 SDPA 的 8.26 s / 35.12 GB。

4 · 数据与训练:138M 条查询是怎么造出来的

方法只解决「怎么解码」,覆盖七类任务靠的是数据引擎——以及一条「先知识、后定位」的训练顺序。

4.1 LocateAnything-Data

总量:12M 唯一图像、138M+ 自然语言查询、785M 标注框、22M+ 负样本。任务构成(查询占比): 通用检测 66.9%(框占 83.1%)、GUI grounding 16.5%、referring 7.3%、OCR 3.6%、文档版面 3.5%、点定位 2.2%。 数据引擎(附录 B.2)按来源分两条线:

  • 有标注线(OpenImages、Objects365):把框类别交给 Qwen3-VL 生成属性/空间/推理式查询 → Molmo 预测候选点 → 只保留落在 GT 框内的点作监督。
  • 无标注线(Unsplash、SA-1B):Qwen3-VL 直接生成查询 → Molmo 打点 + SAM 3 转框,或 Rex-Omni 直接出框。
  • 统一质检:全部生成框经 Qwen3-VL post-checking 过滤不一致预测;GroundCUA 的短标签也由 Qwen3-VL 从 appearance / spatial / functional 三角度扩写。

值得注意:整条数据引擎建立在 Qwen3-VL + Molmo + SAM 3 + Rex-Omni 上——标注质量的上限就是这组「教师」的上限, 而最终质检又闭环回到 Qwen3-VL,自评自洽的风险论文未讨论。

4.2 训练流程:先世界知识,后定位

四阶段(附录 A,Table 7):先对 base VLM 做 world-knowledge alignment——完全排除检测/grounding 数据, 只用 caption/VQA/OCR 等保住通用能力;再三阶段 SFT:Stage-1 混入全量 138M 查询;Stage-2 把通用数据降至 20%、加权多目标密集数据(MOT20Det、SKU110K)。GPU 规模 64 → 256 张,lr 2e-4 → 1e-5, 序列长 32,768 / 25,600;总机时未披露。消融实验模型只在 COCO 上训练,以隔离 PBD 本身的贡献。 推理配置(附录 A):temperature 0.7、top-p 0.9、repetition penalty 1.1、block size 6、max_new_tokens 8192、BF16; BPS 指标在单张 H100 上测量。

5.3 消融与「诚实数字」

消融(仅 COCO 训练,Table 6)回答三个问题:① 块化表示本身有用吗?——Textual 49.1 / Quantized 50.1 / PBD-Slow 52.1(同 BPS 下 +2.0);② 与结构无关的并行方案比呢?——SDLM-B4/6/8 = 46.5/46.1/45.8、 Block Diffusion 44.8,全部远低于 PBD-Fast 的 49.6,且 BPS 只有其三分之一;③ 联合损失关键吗?——L_ntp+L_blk 把 Slow 上界从 50.1 推到 52.1,只用 L_blk 的 Fast 掉到 47.2。框排序用 X-Y Corner Order 最优; 换骨干 Qwen3-VL-4B 复现同样成立(NTP 50.8 → PBD-Hybrid 52.0,BPS 2.8 → 9.4),方法可迁移。

⚠️ 论文自己埋的「诚实数字」:OCR 上 Fast/Hybrid 救不回来。模式对比(附录表): 吞吐 Fast 15.3 / Hybrid 12.7 / Slow 4.3 BPS;但 HierText 上 28.8(Fast)/ 29.1(Hybrid)/ 43.2(Slow), SROIE 上 38.8 / 39.3 / 64.4(Slow)——小字密排场景并行块解码精度腰斩,Hybrid 的回退机制也兜不住。 默认主表全是 Hybrid 口径,部署到 OCR 类负载时这组数字必须先看。

6 · 局限与冷思考

作者自述

  • 只用了 SFT,没用 RL(§5 Limitation):RL 优化块级解码策略、降低回退频率被列为 future work。
  • 两类失败模式(§3.3):类别边界的 Format Irregularity 与网格密集排列的 Spatial Ambiguity——Hybrid 回退是补丁而非根治。

我读出的(文中未明说)

  • OCR 是块并行的真实软肋:小字密排时坐标高度歧义,块内并行同时猜 4 个坐标的联合分布很难学;Slow 模式 43.2/64.4 vs Hybrid 29.1/39.3 意味着「默认 Hybrid」的营销口径在 OCR 负载上不成立。
  • 开源成色要打折:权重是 NVIDIA 非商用许可(仅学术研究);号称公开的数据集 nvidia/LocateAnything-Data 实际是 gated 需申请;当前发布权重不支持 visual prompt 推理(GitHub Note);模型默认不输出确定性置信度(第三方论文需自构 pseudo-confidence)。
  • 数据引擎的自洽闭环:查询生成、伪标注、最终质检全部经由 Qwen3-VL 一系模型,教师偏置会直接写进 138M 条监督里;论文没有对数据引擎本身的错误率做审计。
  • 成本黑箱:四阶段最多 256 张 GPU,但总机时/数据生产成本未披露;「12M 图 785M 框」的规模叙事与可复现性之间有距离。
  • 传播与学术认可不对称:HF 一周 10 万+ 下载、集成进 Nemotron 3 Nano Omni,但 HN 讨论帖只有 2 分 0 评论;ECCV 2026 接收目前仅有官方 README 与作者主页佐证。
💡 对我们的特别相关性:这个 NVIDIA SOTA grounding 模型的骨架是「中国制造」——视觉编码器是月之暗面 Kimi-VL 的 MoonViT-SO-400M(MIT 许可),语言模型是 Qwen2.5-3B-Instruct, 数据引擎重度依赖 Qwen3-VL(查询生成 + 全部伪标注质检),主要 baseline Rex-Omni / Qwen3-VL / MiMo-VL / GUI-Owl / MAI-UI 等也几乎全是中文开源 VLM 的点名册。它是观察「中文开源组件如何进入 NVIDIA 产品线」 (Nemotron / Cosmos)的一个干净样本;PBD 的块对齐思路对我们自己的 grounding/GUI 数据与推理栈也有直接可迁移性。
